## 1. Bug: TIME_TP não fechava posição lucrativa

### Problema
Posição NEAR a +5.58% ROI não foi fechada pelo bot. Virou -6.33% e fechou em prejuízo (-3.48 USDC).

**Causa:** TIME_TP exigia **simultaneamente** 30 minutos aberto E ROI ≥ 5%. NEAR atingiu +5.58% aos 23 minutos — antes dos 30 min mínimos.

```python

TIME_TP_MIN_MIN  = 10    # minutos mínimos para TIME_TP (era 30)
```

### Fix aplicado — `execution.py`
```python

    _registar_fecho(...)

    continue

# Saída por tempo + ROI ≥ 5%

    ...
```

## 2. Bug: Profit Lock — stop loss não subia correctamente

### Problema
O sistema de profit lock não estava a colocar o stop na exchange. Posição ficou sem protecção apesar de ter +29% ROI em aberto.

**Causa:** `lock_price = entry + new_lock / qty` resulta em preço quase igual ao preço de mercado actual. Binance rejeita stops a menos de ~0.1% do mark price.

### Fix aplicado — `execution.py`
```python
# Stop no nível ANTERIOR garante distância mínima ao preço actual
lock_usdc = max(new_lock - PROFIT_LOCK_STEP, 0.0)
if side == "LONG":
    lock_price = round(entry + lock_usdc / qty, 8) if lock_usdc > 0 else round(entry * 1.0005, 8)
else:
    lock_price = round(entry - lock_usdc / qty, 8) if lock_usdc > 0 else round(entry * 0.9995, 8)

# Retry 3x com buffer crescente de 0.15%
for attempt in range(3):
    new_lock_id = place_stop_market(symbol, lock_side, lock_price, qty)
    if new_lock_id:
        break
    if side == "LONG":
        lock_price = round(lock_price * (1 - 0.0015), 8)
    else:
        lock_price = round(lock_price * (1 + 0.0015), 8)
    time.sleep(0.5)
```

## 4. Bug: `place_stop_market` — erro "algotype"

### Problema
```
Mandatory parameter 'algotype' was not sent, was empty/null, or malformed
```

**Causa:** Parâmetros enviados como query string em POST. Binance exige body para `/fapi/v1/algoOrder`.

### Fix — `exchange.py`
```python
r = requests.post(
    f"{BASE_URL}/fapi/v1/algoOrder",
    data=signed, headers=_headers(), timeout=10  # ← body, não params
)
data = r.json()
if data.get("code") == -1102 and "algotype" in str(data.get("msg", "")).lower():
    # Fallback: query string
    r = requests.post(
        f"{BASE_URL}/fapi/v1/algoOrder",
        params=_sign(params), headers=_headers(), timeout=10
    )
```

## 5. Bug: Guard de margem afectado por posições USDT-M

### O que aconteceu (07:43 UTC)
- Utilizador tinha TAGUSDT SHORT a 30x com -5.23 USDC (-51.66%)
- `get_margin_ratio()` lia `totalMaintMargin / totalMarginBalance` — CONTA INTEIRA incluindo USDT-M
- Rácio global ultrapassou 35% → guard disparou → fechou trades do bot (ENAUSDC + DOGEUSDC)
- Provávelmente liquidação cruzada do Binance fechou EDENUSDT, BSBUSDT, TAGUSDT ao mesmo segundo

### Fix — `exchange.py`
```python
def get_margin_ratio() -> float | None:
    """Rácio só do activo USDC/BNFCR — não afectado por posições USDT-M."""
    ...
    for asset in data.get("assets", []):
        if asset.get("asset") in ("USDC", "BNFCR"):
            maint   = float(asset.get("maintMargin",   0) or 0)
            balance = float(asset.get("marginBalance", 0) or 0)
            if balance > 0:
                return round(maint / balance * 100, 2)
```

## 6. Novo: Guard de Liquidação Global

### Motivação
Utilizador pode não estar no telemóvel. Conta cross-margin partilha margem entre USDT-M e USDC-M. Se posições USDT-M com alta alavancagem acumulam perdas, toda a conta pode ser liquidada.

### Implementação — `exchange.py`
```python
def get_margin_ratio_global() -> float | None:
    """Rácio de TODA a conta (USDT-M + USDC-M). Para guard de liquidação."""
    maint   = float(data.get("totalMaintMargin",  0))
    balance = float(data.get("totalMarginBalance", 0))
    if balance > 0:
        return round(maint / balance * 100, 2)
```

### Parâmetros — `config.py`
```python
LIQUIDATION_GUARD_PCT = 50.0  # > 50% → fecha posições a positivo
LIQUIDATION_WARN1_PCT = 40.0  # aviso 🟡
LIQUIDATION_WARN2_PCT = 55.0  # aviso 🟠
LIQUIDATION_WARN3_PCT = 70.0  # aviso 🔴
```

### Lógica — `execution.py`
| Rácio global | Acção |
|---|---|
| > 40% | 🟡 Alerta Telegram (máx 1 por 5 min) |
| > 50% | 🛡 **Fecha TODAS as posições a positivo** (bot + manuais) |
| > 55% | 🟠 Alerta Telegram |
| > 70% | 🔴 Alerta crítico |

**Excepção deliberada:** Este é o único caso em que o bot fecha posições manuais — para evitar que a liquidação total destrua toda a conta.

O guard corre em **todos os ciclos**, mesmo sem trades do bot abertos.

## 8. Trailing Stop — Explicação da UI Binance

### Dúvida do utilizador
"Porque é que colocar trailing stop a 550 diminui o total da minha carteira?"

### Resposta
O "Valor da Posição" mostrado na UI é o valor **nocional ao preço de activação**, não o saldo real:
- Com activation 550: 3.2 ZEC × 550 = 1,761 USDC
- Sem activation (preço actual ~584): 3.2 ZEC × 584 = 1,870 USDC

Não é o saldo que diminui — é apenas a UI a calcular o notional ao preço de activação em vez do preço actual.

## Lições aprendidas

1. **Conta cross-margin é partilhada** — USDT-M e USDC-M usam o mesmo pool de margem. Alavancagem alta em USDT-M pode liquidar toda a conta incluindo trades do bot.
2. **Binance rejeita stops a < ~0.1% do mark price** — o profit lock tem de usar o nível anterior, não o nível actual.
3. **TIME_TP com 30 min mínimos era demasiado conservador** — reduzido para 10 min + ROI_TP_IMEDIATO a 7% para capturas rápidas.
4. **`pending_sync` deve ser escrito DEPOIS de verificar se já existe posição** — a ordem do código é crítica.
5. **Nunca misturar leverage >10x em USDT-M com conta cross-margin** — 30x TAGUSDT é suficiente para liquidar toda a conta.
